Retail Sales Management System

3-Tier Desktop Architecture and Real-Time Inventory Control in Java

Developed a robust 3-Tier desktop sales and stock application utilizing Java Swing and MySQL, engineered to substitute error-prone manual bookkeeping with structured database automation, transactional inventory control, and secure credential handling[cite: 2].

About This Project

The system adheres strictly to a decoupled 3-Tier Architecture to secure modular operations[cite: 2]. The Presentation Layer utilizes graphical frames (like LoginUI and MainDashboard) via JTabbedPane components to separate stock workflows from business evaluations[cite: 2]. The Business Logic Layer handles computation filters, including automated total calculations and an 18% VAT module matched to Sri Lankan operational standards[cite: 2]. Finally, the Data Access Layer isolates communication queries within specific Model modules and Data Access Objects (DAOs), minimizing architectural dependencies throughout runtime operations[cite: 2].

Java (JDK 21) Java Swing API 3-Tier Architecture MySQL Database XAMPP / phpMyAdmin Singleton Connection Pattern Data Access Objects (DAO) PreparedStatements Security NetBeans IDE

Key Highlights

  • Decoupled Architecture Framework: Formulated an organized 3-Tier Model-View-Controller design sequence that abstracts backend SQL data retrieval mechanics cleanly away from graphical interfaces[cite: 2].
  • Automated Stock Decrementation: Engineered transactional trigger layers that automatically subtract sold units from target product inventory counts immediately upon sale finalization[cite: 2].
  • Secure Injection Defenses: Safeguarded database interactions against script exploitation by running query allocations exclusively through parameterized SQL PreparedStatements[cite: 2].
  • Relational Schema Modeling: Structured database connections to maintain intricate One-to-Many relational bounds, ensuring line items are bound directly to their parent transaction headers[cite: 2].
  • Singleton Resource Optimization: Programmed a centralized database initialization node to enforce a strict Singleton structure, mitigating memory overhead by sharing one global connection index[cite: 2].
  • Encapsulated Data Validation: Upheld strict object-oriented paradigms by completely protecting database profiles behind private attributes accessible only via public access points[cite: 2].

Technical Architecture & Design

The application encapsulates physical business entities—such as Products, Customers, Sales, and SaleItems—within structured model boundaries[cite: 2]. By relying on class composition, the system guarantees strong data integrity rules; line items are structurally prevented from existing unless linked directly to an overarching transaction entity[cite: 2].
